# Feature Specification: 長輩用藥說明與個人紀錄

**Feature Branch**: `main`（功能目錄：`001-medicine-records`；本次未建立功能分支）

**Created**: 2026-10-11

**Status**: Draft

**Input**: User description: "建立家族限定的長輩用藥說明與個人紀錄系統。長輩可拍攝、
上傳或手動輸入藥袋資訊，逐筆確認後保存個人紀錄；管理員可管理帳號與資料。系統僅
整理藥品一般用途與官方來源，不提供診斷或個人化用藥建議。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 建立並確認個人用藥紀錄 (Priority: P1)

長輩登入後，能以手機拍照、從相簿選擇照片，或手動輸入方式建立一次用藥紀錄。系統
先將辨識結果列為草稿，長輩逐筆核對藥名、劑量、頻率、天數及備註後，才會保存為正式
個人用藥紀錄。

**Why this priority**: 這是讓長輩將新取得藥袋轉為可持續查閱紀錄的核心價值；沒有此
流程，系統無法保留個人的用藥脈絡。

**Independent Test**: 使用一組含多項藥品的藥袋資料，長輩可完成輸入、修改候選內容、
確認並在自己的清單中看到對應紀錄；未確認的草稿不得出現在正式清單。

**Acceptance Scenarios**:

1. **Given** 長輩已登入且尚未建立新紀錄，**When** 長輩拍攝或上傳一張以上藥袋照片，
   **Then** 系統顯示照片預覽，並允許長輩更換、移除或補充照片後再繼續。
2. **Given** 系統已從照片或手動輸入建立候選藥品項目，**When** 長輩核對並確認每一項
   必填處方資訊，**Then** 系統保存一次就診脈絡及其藥品項目為正式個人紀錄。
3. **Given** 候選藥品中有文字不清、資料矛盾或多個可能對應項目，**When** 長輩尚未明確
   選擇或更正，**Then** 系統將該項標示為待確認，且不得將其保存為已確認用藥。
4. **Given** 長輩選擇手動輸入，**When** 長輩填寫藥名與可取得的處方資訊，**Then** 系統
   允許建立待確認草稿，並以相同確認規則保存。

### User Story 2 - 查看自己的藥品說明與就診脈絡 (Priority: P1)

長輩能在大字、全繁體中文的介面查看自己的已確認藥品，了解該藥的一般常見用途、
本次處方用法、來源資料，以及此次就診原因、科別與醫師或藥師交代。

**Why this priority**: 長輩的主要需求是知道每一顆藥「一般是做什麼」以及「這次為何
開立」，並能在日後回看，不必每次重新詢問。

**Independent Test**: 建立一筆已確認紀錄後，以該長輩帳號登入，可在不查看其他人資料
的前提下找到藥品、處方用法、一般用途、來源與就診脈絡。

**Acceptance Scenarios**:

1. **Given** 長輩有已確認藥品，**When** 長輩開啟藥品詳情，**Then** 系統顯示原處方的
   劑量、頻率、天數與備註，並與一般用途明確區隔。
2. **Given** 藥品已可靠對應官方資料，**When** 長輩查看一般用途，**Then** 系統顯示易懂
   說明、官方資料來源連結及資料比對狀態。
3. **Given** 長輩查看任何藥品說明，**When** 頁面載入，**Then** 系統明確提醒該內容不是
   診斷或個人化用藥建議，且不得自行停藥、換藥或調整劑量。
4. **Given** 藥品未可靠對應官方資料，**When** 長輩查看該項目，**Then** 系統顯示待確認
   狀態與詢問醫師或藥師提示，而非提供確定的藥品用途。

---

### User Story 3 - 管理家人帳號與紀錄 (Priority: P2)

管理員能建立及停用長輩帳號、協助建立或修正長輩的紀錄、在必要時受控刪除資料，並
查閱管理操作紀錄。長輩只能讀取與管理自己的資料，不能查看其他家人資料或自行刪除
帳號與紀錄。

**Why this priority**: 本系統僅提供指定家人使用，需要由單一管理員協助首次設定與處理
資料維護，同時維持個人資料隔離。

**Independent Test**: 建立兩個長輩帳號與一個管理員帳號；驗證長輩彼此無法讀取對方資料，
管理員可代為建立、修正與受控刪除紀錄，且每次管理操作均可追溯。

**Acceptance Scenarios**:

1. **Given** 管理員已登入，**When** 管理員建立長輩帳號並設定初始密碼，**Then** 新帳號
   可登入，且首次登入時看到可略過的修改密碼建議。
2. **Given** 長輩已登入，**When** 長輩瀏覽用藥資料或嘗試以任何入口存取其他人的資料，
   **Then** 系統只提供自己的資料，並拒絕未授權存取。
3. **Given** 管理員修改、停用或刪除帳號、紀錄或照片，**When** 操作完成，**Then** 系統
   保存可辨識操作者、時間、動作與對象的稽核紀錄。
4. **Given** 長輩不再需要某筆資料，**When** 長輩要求刪除，**Then** 系統指示其聯絡管理員，
   而不提供自行刪除功能。

---

### User Story 4 - 保存可核對的原始資料 (Priority: P2)

長輩與管理員能在已授權範圍內回看用來建立紀錄的原始藥袋、處方箋或藥盒照片，以便
核對辨識結果與處方文字。原始照片會長期保留，且不對未授權者公開。

**Why this priority**: 原始照片是辨識結果的可核對依據，可降低抄寫或辨識錯誤造成的
誤解。

**Independent Test**: 上傳一張照片並完成紀錄後，該長輩與管理員可查看照片；另一名長輩
無法查看或取得該照片。

**Acceptance Scenarios**:

1. **Given** 長輩已將照片連結至自己的紀錄，**When** 長輩或管理員開啟該紀錄，**Then**
   系統只在授權範圍內提供原始照片檢視。
2. **Given** 未授權使用者嘗試開啟其他人的原始照片，**When** 系統驗證存取權限，**Then**
   系統拒絕提供照片內容。

### Edge Cases

- 藥袋文字模糊、反光、裁切不完整或照片格式不受支援時，系統必須說明問題並允許重拍、
  換圖或改用手動輸入，不得憑猜測確認藥品。
- 同一藥名可能有不同劑型、劑量或多個官方候選資料時，系統必須要求使用者或管理員
  明確核對，不能自動選擇。
- 使用者中斷建立流程、網路短暫失敗或尚未完成確認時，未確認資訊不得被當成正式用藥
  紀錄；使用者須能辨識該資料仍為草稿或待確認。
- 來源資料暫時無法取得或無法對應時，系統仍可保存使用者已確認的原始處方文字，但必須
  標示沒有可靠的官方說明來源。
- 管理員停用帳號後，該帳號不得再登入或讀取資料；既有紀錄是否保留依管理員受控操作
  處理，且操作必須可追溯。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 僅允許由管理員建立或啟用的使用者帳號登入；系統 MUST NOT
  提供公開註冊。
- **FR-002**: 系統 MUST 區分管理員與長輩使用者角色；長輩使用者 MUST 只能存取自己的
  帳號、用藥紀錄與原始照片，管理員 MUST 可依授權管理所有家人成員的資料。
- **FR-003**: 管理員 MUST 能建立、停用與協助重設長輩帳號；新帳號 MUST 由管理員設定
  初始密碼。
- **FR-004**: 長輩使用者首次登入時 MUST 看到修改初始密碼的建議，且系統 MUST NOT
  強制其在繼續使用前修改；使用者 MUST 能在日後自行修改自己的密碼。
- **FR-005**: 系統 MUST 讓使用者以手機拍照、選取相簿照片或手動輸入方式建立用藥資料。
- **FR-006**: 系統 MUST 在照片處理前顯示使用者選擇的照片，並允許新增、移除或更換照片。
- **FR-007**: 系統 MUST 將影像或手動輸入產生的候選藥品資料標示為草稿或待確認；候選資料
  MUST NOT 在未確認前成為正式用藥紀錄。
- **FR-008**: 系統 MUST 讓使用者或管理員逐項檢查及修正藥名、劑量、頻率、天數與備註，
  再明確確認保存。
- **FR-009**: 系統 MUST 將每次確認保存的藥品項目連結至此次就診原因、就診科別與醫師或
  藥師交代；上述欄位在資料缺少時 MUST 清楚標示未提供。
- **FR-010**: 系統 MUST 顯示藥品的一般常見用途與本次處方資訊，且 MUST 清楚區分兩者。
- **FR-011**: 系統 MUST 優先比對台灣官方藥品資料，並為已比對項目顯示來源連結、比對狀態
  與可取得的來源更新資訊。
- **FR-012**: 系統 MUST 將無法唯一確認、資訊矛盾或無官方可靠來源的藥品標示為待確認，
  並提示使用者核對藥袋或詢問醫師、藥師；系統 MUST NOT 將此類資料描述為確定結果。
- **FR-013**: 系統 MUST 在所有藥品說明與確認流程顯示非醫療建議聲明，明確告知使用者
  不得自行開始、停止、更換或調整藥物與劑量。
- **FR-014**: 系統 MUST NOT 根據藥品、照片、對話或既有紀錄診斷疾病、推論疾病階段，
  或宣稱病情改善、惡化。
- **FR-015**: 系統 MUST 長期保存使用者上傳的原始照片與其所屬紀錄關聯，且 MUST NOT 將
  原始照片公開給未授權者。
- **FR-016**: 長輩使用者 MUST NOT 自行刪除帳號、用藥紀錄或原始照片；系統 MUST 指引其
  聯絡管理員處理。
- **FR-017**: 管理員 MUST 能代表長輩建立或修正用藥紀錄，並能依受控程序刪除帳號、紀錄
  或照片。
- **FR-018**: 系統 MUST 為管理員的帳號、紀錄與照片管理動作保存稽核紀錄，至少包含操作者、
  時間、動作與受影響對象。
- **FR-019**: 系統 MUST 以全繁體中文提供介面與系統說明，並提供適合長輩閱讀的大字與
  簡化主要操作入口。
- **FR-020**: 系統 MUST 保留未來加入國語及台語語音朗讀的內容空間，但第一版 MUST NOT
  將語音朗讀列為必要功能。
- **FR-021**: 第一版 MUST NOT 提供每日服藥打卡、吃藥提醒、用完提醒、回診提醒、藥物過敏
  或不良反應紀錄功能。
- **FR-022**: 所有正式紀錄的顯示與權限判斷 MUST 以後端保存的確認結果為準；用戶端暫存、
  未確認草稿與 AI 候選內容 MUST NOT 覆寫正式紀錄。

### Requirement Acceptance Coverage

- **FR-001 至 FR-004**: 由 User Story 3 的情境 1 至 4、SC-003 與 SC-006 驗收。
- **FR-005 至 FR-008**: 由 User Story 1 的情境 1 至 4、SC-001 與 SC-004 驗收。
- **FR-009 至 FR-014**: 由 User Story 2 的情境 1 至 4、SC-002 與 SC-005 驗收。
- **FR-015 至 FR-018**: 由 User Story 3 的情境 2 至 4、User Story 4 的情境 1 至 2、
  SC-003 與 SC-006 驗收。
- **FR-019 至 FR-021**: 透過長輩使用者的主要流程驗收、介面文字檢查與範圍檢查驗收；
  任何不屬於第一版範圍的功能不得出現在已核准交付項目。
- **FR-022**: 由 User Story 1 的情境 2 至 3、SC-004，以及跨帳號權限驗收共同驗收。

### Key Entities *(include if feature involves data)*

- **使用者帳號**: 可登入的家人身分，具有長輩使用者或管理員角色、啟用狀態與顯示名稱。
- **就診脈絡**: 一次建立用藥資料所對應的就診日期、原因、科別與醫師或藥師交代；不代表
  系統診斷或疾病階段。
- **用藥紀錄**: 經使用者或管理員明確確認的處方項目集合，包含處方文字、確認狀態與所屬
  就診脈絡。
- **藥品項目**: 一筆處方中的單一藥品及其藥名、劑量、頻率、天數、備註、來源比對狀態與
  一般用途說明。
- **原始照片**: 用於建立或核對紀錄的藥袋、處方箋或藥盒影像，與其所有者及用藥紀錄關聯。
- **官方藥品參考資料**: 台灣官方來源提供的藥品資訊及其來源連結、更新資訊與對應狀態。
- **稽核紀錄**: 管理員對帳號、紀錄或照片執行的可追溯管理動作。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在可讀且完整的藥袋資料測試中，至少 90% 的測試使用者能在 5 分鐘內完成
  拍照或上傳、核對並保存一筆含一項藥品的用藥紀錄，且不需協助。
- **SC-002**: 100% 已確認的用藥紀錄均能顯示確認後的處方資訊、所屬就診脈絡，以及官方
  來源比對狀態或明確的待確認原因。
- **SC-003**: 權限驗收測試中，100% 嘗試跨帳號讀取紀錄或原始照片的長輩使用者請求皆被拒絕；
  管理員可在授權範圍內完成相同資料的管理操作。
- **SC-004**: 100% 未完成逐項確認的候選資料都不會出現在正式用藥清單中。
- **SC-005**: 100% 藥品說明頁與確認頁皆顯示非醫療建議聲明；針對無法可靠比對的測試資料，
  系統皆顯示待確認與詢問專業人員提示，而非確定的藥品用途。
- **SC-006**: 管理員帳號、紀錄與照片管理操作的驗收測試中，100% 已完成操作都可找到包含
  操作者、時間、動作與對象的稽核紀錄。

## Assumptions

- 第一版服務對象為少數受邀家人，主要使用台灣的處方箋、藥袋與藥盒，且介面固定為
  繁體中文。
- 長輩可在需要時由管理員協助首次帳號設定與建立第一筆紀錄，但每位長輩使用自己的帳號。
- 使用者會在上傳前取得藥袋或處方箋影像的使用權，並同意長期保存其原始照片以供日後核對。
- 藥品一般用途以台灣官方資料為優先依據；資料不完整或無法可靠對應時，系統以待確認處理，
  不以推測補足。
- 管理員是帳號、資料刪除與存取問題的單一聯絡窗口；第一版不提供使用者自助刪除流程。
- 本功能不替代醫師、藥師或其他醫事人員的診斷與用藥指導。
